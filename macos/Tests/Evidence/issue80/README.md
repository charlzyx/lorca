# Issue #80 AppKit UI evidence

These PNGs capture the production `OutputsViewController` and `OutputRow` views from native AppKit/XCTest. The harness uses synthetic records, an example.com document reference, fixed timestamps and a generated sample chart. No real account, provider credentials or private chat is loaded. It renders the content area on the native window background with an offscreen window; the screenshots do not include macOS title-bar or sheet materials.

- `outputs-empty.png`: the added Outputs sheet before any outputs are present.
- `outputs-versions.png`: immutable report versions, newest first, with producing bot/task provenance, synthetic passed/failed test results and Open document.
- `outputs-file-ready-before.png`: the same single-file fixture rendered by the view at `307ece6`, before the short-list alignment fix; the result sits at the bottom of the viewport.
- `outputs-file-ready.png`: the corrected top-aligned single-file result with a real local PNG thumbnail and enabled Preview, Open and Save As controls.
- `outputs-file-unavailable.png`: the production output row after the disconnected local CLI client returns its error, showing the reason and Retry. The fixture never starts or connects to a CLI.

Regenerate the current screenshots from this worktree:

```sh
LORCA_MOCK=1 LORCA_CAPTURE_OUTPUTS_UI=1 swift test --package-path macos --filter testCaptureOutputsSheetStates
LORCA_MOCK=0 LORCA_CAPTURE_OUTPUTS_UI=1 swift test --package-path macos --filter testCaptureUnavailableFileRow
```

`OutputEvidenceCaptureTests.swift` skips capture unless explicitly enabled. Files live outside the app's Sources and Resources and outside the Swift test target, so they are not included in production bundles. The before image is retained as a historical capture rather than regenerated by the current view.

The captures establish native rendering, list placement, version/evidence labels and control availability with test data. They do not exercise Quick Look, external file handlers, document reachability, paired browser controls, or combined #72/#85 workflows. Those QA and consolidation limitations remain in PR #87.
